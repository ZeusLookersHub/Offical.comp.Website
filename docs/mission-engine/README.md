# Lookers AI — Mission Engine

ده قلب الأداة: من أول ما المستخدم يختار المهمة من الكواكب، لحد ما يأكد البريف.
الكود في `core/mission-engine/`، والاختبارات في `tests/mission-engine.test.ts` (`npm run test:mission-engine`).

## المبدأ

- **القواعد هي اللي بتقرر.** هي اللي تحدد السؤال الجاي، وإمتى نقف، وإيه اللي اتأكد.
- **الموديل (في المرحلة التانية على السيرفر) دوره ٣ حاجات بس:** يستخرج المعلومات، ويكتب الناتج، ويراجعه.
- **مفيش دليل = مفيش معلومة.** أي قيمة بتتسحب من كلام المستخدم لازم يكون معاها الجملة اللي قالها. وأسماء البراند والكلام الحرفي لازم يكونوا موجودين في كلامه **بالحرف**.
- **أقل أسئلة ممكنة.** الخانات ليها ٣ مستويات:
  - `critical`: بنسأل عليها دايماً.
  - `important`: بنسأل عليها في حدود عدد الأسئلة المسموح (`questionBudget`)، وبعد كده نستخدم القيمة الافتراضية.
  - `nice`: ما بنسألش عليها خالص. القيمة الافتراضية بتظهر في البريف، والمستخدم يقدر يعدلها.
- **الافتراضات مكشوفة.** كل قيمة افتراضية بتظهر في البريف ومعاها السبب.

## المسار

```
nextStep → intake (الفكرة) → submitIntake → question … answer/skip → brief → confirmBrief
→ buildComposeRequest (للسيرفر) → runGates على الناتج → repairInstruction لو في فشل
```

- **التعديل بعد التأكيد:** `answer` بيعدل خانة واحدة، ويرجّع البريف لحالة "محتاج تأكيد".
- **الاقتراحات الحيّة:** `suggest(blueprint, slotId, typed, session)` بتطلع chips فورية وانت بتكتب. ولما السيرفر يدخل، هيزود عليها أفكار من الموديل.

## الـ Blueprint

بيانات بس، من غير كود. ده عشان نقدر بعدين ننقله لقاعدة البيانات، ونعمل له إصدارات. كل Blueprint فيه:
- سؤال الفكرة، وأمثلة البداية (starters).
- الخانات (slots) بأسئلتها وشرحها ومثالها.
- الاختيارات، والكلمات اللي بتختارها تلقائياً.
- القيم الافتراضية بشروطها، والمفردات بتاعة الاقتراحات.
- عقد الناتج (output contract).
- بوابات الجودة (gates).
- الأدوات المستهدفة.
- تعليمات الكتابة للموديل.

أول Blueprint كامل هو `product-photo`. بيسأل من صفر لـ ٤ أسئلة بعد الفكرة. والبوابات بتمسك:
- اسم البراند لو اتغير (حالة DAVIDOFF ← DAVIE DOVE).
- الكلام الحرفي لو اتغير.
- المقاس لو غلط.
- إعدادات الأداة لو دخلت في وصف المشهد.
- أي كلام متألف على الصورة.
- البرومبت لو مش بالإنجليزي.

## الطبقات الأربعة

كل خانة في الـ Blueprint تبع طبقة واحدة بس. والبرومبت الداخلي اللي بنبعته لموديلنا بيتبني من الطبقات الأربعة بالترتيب، عن طريق `compileSystemPrompt`.

| الطبقة | مسؤولة عن إيه | بتقدّم إيه |
|---|---|---|
| ١ · الفهم | الهدف، والموضوع، والجمهور، ومكان الاستخدام، والمعلومات المتاحة | صورة صح للمطلوب من معلومات مؤكدة بس |
| ٢ · التفكير | الستايل، والهيكل، والترتيب، ومعايير القرار | القرارات اللي كان المستخدم هياخدها لوحده، بخبرة متخصص |
| ٣ · التحكم | الأسماء والكلام الحرفي، والممنوعات، واللي ممنوع نخترعه | حماية من أخطاء الـ AI المعروفة |
| ٤ · التسليم | شكل الناتج، والأداة، والمقاس أو المدة، واللغة، والفحوصات | نتيجة جاهزة للنسخ وعدّت الفحوصات |

مهمات النصوص (العرض الاستثماري وصفحة الهبوط) بيطلع ليها برومبت نهائي متقسم بنفس الطبقات تحت عناوين:
- Goal
- Approach
- Rules
- Output

أما مهمات الصور والفيديو، فبيطلع ليها وصف مشهد مركّز، لأن ده اللي أدواتها بتفهمه.

## المهمات المتبنية (٢٢ وبيزيدوا)

- **صور/فيديو:** صورة منتج، فيديو منتج.
- **عروض/ويب:** عرض استثماري، صفحة هبوط.
- **عالم الأعمال (كامل):** استراتيجية، خطة عمل، دراسة جدوى، تحليل منافسين، تسعير، SWOT، دخول السوق، خطة مالية، تموضع البراند، نموذج العمل.
- **عالم الكتابة:** إعلان مكتوب، إيميل، كابشن سوشيال، مقال، نصوص موقع، وصف منتج، سكريبت فيديو، بيان صحفي.

**الطريقة في البناء بالجملة:**
- مهمات النصوص بتتبني من مصنع `makeTextMission` في `blueprints/_text.ts` (عقد + فحوصات: الاسم بالحرف، مفيش أرقام متألفة، RTL + أدوات النص + خانات موحّدة). كل مهمة جديدة = إعداد مختصر.
- مهمات الصور/الفيديو بتتبني من الوحدات في `modules.ts` + أمثلة بصرية لكل اختيار.

**الباقي (جاي عالم ورا عالم):** تصميم، فيديو (توسيع)، تسويق، عروض (توسيع)، تكنولوجيا، داتا، بحث، أتمتة، مهنة/تعلّم، خدمة — من عائلات `lookersAiTopicRegistry`.

**التحديث:** بعد أي دفعة بلوبرنتس: `npm run build:engine-blueprints` ← commit/push ← تحديث صف `lookers_engine_config` بالـ commit والـ SHA-256 (المحرك بيلتقطها خلال ٥ دقايق من غير نشر).

## السيرفر (`server/engine` ← `supabase/functions/lookers-ai-engine`)

- `intake`: الموديل بيقترح معلومات من رسالة المستخدم، وأي اقتراح من غير دليل حرفي بيترفض.
- `ideas`: اقتراحات بتتبني على اللي المستخدم بيكتبه.
- `compose`: البرومبت الداخلي ← ناتج حسب العقد ← الفحوصات ← إصلاح واحد موجّه لو حاجة فشلت ← النتيجة ومعاها تقرير الفحوصات.
- `describe`: قراية الصورة بـ Gemini (وصف + معلومات بدليل).

### الموديلات

- **الموديل الأساسي بيتحدد من المفاتيح المتاحة، بالترتيب ده:** Gemini (لو `GEMINI_API_KEY` موجود) ← DeepSeek ← OpenRouter. وممكن تفرض واحد بـ `ENGINE_PROVIDER`.
- يعني أول ما تضيف `GEMINI_API_KEY`، كل الشغل (الاستخراج والكتابة والفحص والصور) بيتحول لـ Gemini تلقائياً من غير نشر جديد. DeepSeek بيفضل احتياطي.
- الموديل الافتراضي لـ Gemini هو `gemini-3.8-flash`، وممكن تغيّره من `ENGINE_MODEL` (للنص) أو `GEMINI_MODEL` (للصور).

### النشر

- الـ function الحقيقية كبيرة، فمتخزّنة مبنية في الريبو في `supabase/functions/lookers-ai-engine/_bundle.mjs`.
- الـ entrypoint المنشور سطرين بس: بيعمل import للـ bundle ده من الريبو على **commit ثابت**.
- **خطوات أي تعديل في كود السيرفر:**
  1. `npm run build:engine-function` (بيبني `_bundle.mjs`)
  2. commit و push
  3. انشر `index.ts` اللي بيعمل import من رابط الـ raw بالـ commit SHA الجديد.
- **ملحوظة:** الطريقة دي محتاجة الريبو يفضل public، والأحسن على المدى الطويل GitHub Action بـ `SUPABASE_ACCESS_TOKEN`.

والسيرفر **مش بيثق في الجلسة اللي جاية من المتصفح**: بيعيد بناها من القيم الصحيحة بس، ومش بيقبلها إلا لو البريف متأكد.

الموارد المطلوبة مشروحة في `RESOURCES.md`.

## النشر

- **`lookers-ai-engine` منشورة على Supabase (version 5)، و`verify_jwt` شغال.** الـ function القديمة `lookers-ai-generate` ما اتلمستش.
- **الـ Blueprints مش جوه كود الـ function.** الـ function بتقرا رابط `server/engine/blueprints.json` على commit ثابت، والـ SHA-256 بتاعه، من جدول `lookers_engine_config`. بتراجعه كل ٥ دقايق، وبتتأكد من الـ hash قبل ما تستخدم الملف.
- **إضافة أو تعديل مهمة:**
  1. `npm run build:engine-blueprints`
  2. commit و push
  3. تحديث صف واحد في الجدول (الرابط والـ hash).
  - **من غير ما تنشر الـ function تاني.**
- **احتياطي:** لو الجدول مش متاح، بيتستخدم الرابط المكتوب في `blueprints-pin.ts`.
- **قراية الصور:**
  - بتشتغل بـ DeepSeek على نفس المفتاح. الموديل `deepseek-flash` بيقبل صور من سبتمبر ٢٠٢٦، وتقدر تغيّره من `ENGINE_VISION_MODEL`.
  - لو اتضاف `GEMINI_API_KEY`، المحرك هيستخدم Gemini بداله.
  - اختبار حي (١٦ نوفمبر): وصف صورة زجاجة بالمصري، وقرا "DAVIDOFF" بالحرف من الليبل.
- **شرط مهم:** الطريقة دي محتاجة الريبو يفضل public. الأحسن على المدى الطويل يبقى في GitHub Action ينشر الـ bundle كامل، باستخدام `SUPABASE_ACCESS_TOKEN`.
- **اختبار حي (١٥ نوفمبر):**
  - `intake`: طلّع المنتج والبراند والاستخدام والإحساس من رسالة عربي واحدة، وكل معلومة معاها دليلها.
  - `compose`: لبرفان DAVIDOFF عدّى ٥ من ٥ فحوصات من أول محاولة، والنتيجة اتحفظت.
  - اتمسح المستخدم التجريبي والنتيجة بتاعته بعد الاختبار.

## الشات على الموقع

- **مهمات التجربة الأربعة بتفتح على `components/LookersMissionChat.tsx`:**
  - صورة منتج
  - فيديو منتج
  - عرض استثماري
  - صفحة هبوط
- **باقي المهمات مكملة على الشات القديم من غير أي تغيير.**
- **المسار:**
  - **الفكرة:** المستخدم يكتبها، والشات يرد بـ "فهمت:" ويعرض اللي استخرجه.
  - **الأسئلة الناقصة بس:** كل سؤال معاه "ليه بنسأل؟" وزرار "تخطّى"، والاختيارات بتظهر بالشرح والمثال البصري.
  - **الاقتراحات:** بتظهر وهو بيكتب، من القاموس ومن الموديل.
  - **البريف:** فيه الحقائق والافتراضات وسبب كل افتراض، وكل حاجة فيه ينفع تتغيّر في مكانها.
  - **"اكتب البرومبت":** النتيجة بتطلع ومعاها:
    - شارة الفحوصات
    - نسخة لكل أداة
    - زرار نسخ
    - قائمة المراجعة
- **الجلسة متحفظة في المتصفح**، فلو الصفحة اتعملها refresh مش هتضيع.
- **الاختبار:** `QA_CHROMIUM_EXECUTABLE=/usr/bin/google-chrome npm run test:mission-chat` بيمشي الرحلة كاملة على الموبايل والديسكتوب، ومعاه mock للسيرفر.
- **ملحوظة:** `npm run build` بيكتب الناتج في `docs/`، لأن ده إعداد GitHub Pages. ما تعملش commit لناتج الـ build على الفرع ده.
